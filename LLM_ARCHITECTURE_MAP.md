# YouTube Automation Pipeline - Full Architecture Map

This document provides a comprehensive overview of the entire YouTube Automation Engine. It is intended to be used as context for any LLM to understand the architecture, database schema, file structure, and data flow of the project.

## 1. High-Level Architecture & Deployment

The system uses a **Hybrid Deployment Architecture** to separate lightweight 24/7 processes from heavy local rendering tasks.

1. **Intake & Bot (Deployed on Railway 24/7)**
   - The Telegram bot (`scripts/telegram_bot.py`) runs continuously on Railway cloud.
   - It acts as the "Approval Gate". You text it video ideas, it saves them to the database, and you can approve them for production via Telegram buttons.

2. **Orchestrator & Rendering (Runs Locally on Mac)**
   - The main daemon (`src/orchestrator.py poll`) runs locally.
   - It polls the cloud database for `approved` videos.
   - It executes the entire AI pipeline (Script -> Audio -> Visuals).
   - It performs the heavy video rendering locally using `Remotion` (React-based renderer) to avoid cloud GPU costs.
   - It publishes the final video to YouTube and sends a Telegram notification.

## 2. Database Schema (Supabase PostgreSQL)

The core state management is handled by a single Supabase table: **`videos`**.

### `videos` Table Columns:
- `id` (UUID): Primary key.
- `source_type` (String): e.g., "manual_telegram", "n8n_scraped".
- `source_video_id` (String/Nullable): Original video ID if scraped.
- `target_title` (String): The idea or title of the video.
- `topic_premise` (String): Expanded description.
- `status` (Enum): Represents the current step in the pipeline.
  - Allowed values: `discovered`, `approved`, `scripting`, `voiceover`, `visuals`, `rendering`, `publishing`, `published`, `failed`.
- `script_payload` (JSONB): Contains the GPT-4o generated script.
  - Structure: `{"title": "...", "description": "...", "scenes": [{"scene_number": 1, "narration": "...", "visual_prompt": "...", "estimated_duration": 5}], "render_progress": 78}`
- `audio_url` (String): Public URL of the generated voiceover MP3 (stored in Supabase Storage).
- `transcript_timestamps` (JSONB): Word-level timestamps generated by ElevenLabs.
- `rendered_video_url` (String): Local path to the final MP4.
- `thumbnail_urls` (Array of Strings): URLs of generated thumbnails.
- `youtube_video_id` (String): The ID of the published YouTube video.
- `error_log` (String): Any error messages from failed steps.
- `created_at` / `updated_at` (Timestamps).

## 3. Data Flow & Pipeline Steps

The pipeline is sequentially driven by `src/orchestrator.py` through the `run_pipeline_for_video(video_id)` function.

### Step 1: Intake (`scripts/telegram_bot.py`)
- User sends a text message to the Telegram bot.
- Bot inserts a row into `videos` with status `discovered` (or asks for approval).
- User clicks "Approve". Status changes to `approved`.

### Step 2: Orchestrator Polling (`src/orchestrator.py`)
- Local script polling Supabase. Finds `approved` video.
- Calls `run_pipeline_for_video`.
- Updates status to `scripting`.

### Step 3: Script Generation (`src/script_generator.py`)
- Uses OpenAI GPT-4o to generate a highly structured JSON script with 35-45 scenes.
- Each scene contains narration text and a visual prompt.
- Updates `script_payload` in Supabase.
- Updates status to `voiceover`.

### Step 4: Voiceover & Timestamps (`src/audio_generator.py`)
- Uses ElevenLabs API (Turbo v2.5 model) to synthesize the full script narration.
- Requests word-level timestamps from ElevenLabs.
- Uploads the `.mp3` to Supabase Storage bucket `audio`.
- Saves timestamps to `transcript_timestamps` in Supabase.
- Updates status to `visuals`.

### Step 5: Visual Sourcing (`src/asset_resolver.py`)
- Iterates over each scene in `script_payload`.
- Queries Pexels API for stock footage matching the scene's `visual_prompt`.
- If Pexels fails, falls back to Fal.ai (Flux) for AI image generation.
- Uploads assets to Supabase Storage bucket `visuals`.
- Injects the `resolved_url` directly into the `script_payload` scene objects.
- Updates status to `rendering`.

### Step 6: Local Rendering (`src/orchestrator.py` & `/renderer-service`)
- Prepares a `props.json` containing the entire `script_payload`, `audio_url`, and `transcript_timestamps`.
- Spawns a local subprocess running `npx remotion render src/index.ts MainVideo ...` inside the `/renderer-service` directory.
- `renderer-service` is a React/Remotion project that fetches the audio and visuals, aligns them using the timestamps, generates dynamic subtitles, and renders an MP4.
- `orchestrator.py` parses the stdout of Remotion (`Rendered X/Y`) and updates `render_progress` inside `script_payload` live.
- Saves the final `.mp4` to the Mac's local drive (`/Users/valsamis/Movies/Automated/`).
- Updates status to `publishing`.

### Step 7: Publishing & Thumbnails (`src/publisher.py`)
- Generates a free AI thumbnail using Pollinations Flux.
- Uses `google-api-python-client` with local OAuth tokens (`token.json`, `client_secrets.json`) to upload the MP4 to YouTube.
- Sets video title, description, and tags based on `script_payload`.
- Uploads the generated thumbnail to the YouTube video.
- Updates status to `published` and saves `youtube_video_id`.

### Step 8: Notifications (`src/notifier.py`)
- Throughout the pipeline, `notifier.py` is called to send Telegram messages.
- Notifies the user upon successful rendering, successful publishing, or if any step fails.

## 4. Folder & File Structure

- **`/src`**: Core Python Backend Pipeline
  - `orchestrator.py`: The main entry point, state machine, and Remotion CLI wrapper.
  - `script_generator.py`: GPT-4o integration.
  - `audio_generator.py`: ElevenLabs API integration.
  - `asset_resolver.py`: Pexels / Fal.ai API integrations.
  - `publisher.py`: YouTube Data API upload and Thumbnail generation.
  - `notifier.py`: Centralized Telegram messaging for alerts.
  - `youtube_uploader.py` / `upload_rendered_video.py`: Helper scripts for YouTube API.

- **`/scripts`**: Utilities & Bots
  - `telegram_bot.py`: The production Telegram Bot (deployed on Railway). Uses long-polling. Handles `/status`, `/queue`, and intake.
  - `outlier_scraper.py` / `manage_channels.py`: Scripts for discovering trending YouTube videos (currently unused/legacy).

- **`/renderer-service`**: Remotion Video Composition Project
  - `src/index.ts`: Remotion Root entry point.
  - `src/MainVideo.tsx`: The main React component that builds the video timeline using the props (audio, scenes, timestamps).
  - Uses TailwindCSS / React.
  - `package.json`: Node dependencies.

- **Root Files**:
  - `render_only.py`: Helper script to manually trigger a render for a specific video ID.
  - `railway.json` & `Dockerfile.worker`: Deployment configuration for the Telegram Bot on Railway.
  - `.env`: Environment variables (API keys, Supabase URLs, Telegram tokens).

## 5. Potential Expansions & Next Steps

When expanding this pipeline, consider the following areas:
1. **Script Upgrades**: Adding "hooks" and "storytelling arcs" in `script_generator.py` prompts.
2. **Visual Upgrades**: Modifying the Remotion React components in `/renderer-service` to add Ken Burns effects (zoom-in/out), kinetic typography (subtitles), and scene transitions.
3. **Audio Upgrades**: Adding background music or sound effects (SFX) in `audio_generator.py` or within the Remotion timeline based on tags generated by GPT-4o.
4. **Thumbnail Generation**: Enhancing the prompts in `publisher.py` or replacing Pollinations with Midjourney API/Fal.ai Flux for ultra-high CTR thumbnails.
